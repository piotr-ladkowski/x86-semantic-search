# doc/x86

Semantic search over x86-64 instruction documentation. Describe what you want to do in plain
English ("count the set bits in a register") and get the right instruction with the essentials for
using it: its forms, the flags it touches, common gotchas and a short example. There is one small
page per instruction, plus a few short articles for ideas that span several instructions.

**v1 scope:** x86-64 long mode, user-space, scalar integer / general-purpose instructions
(see [docs/SCOPE.md](docs/SCOPE.md)). Stack: FastAPI, server-rendered Jinja2 + Tailwind, local
ONNX embeddings, Kubernetes-ready container.

*Naming:* the product is written **doc/x86**; it is spelled `docx86` wherever a slash is not allowed
(Python package, CLI command, container image, Kubernetes objects, `DOCX86_*` environment variables,
trace service name).

# Development

Download the documentation for local llm access
```bash
wget https://cdrdv2-public.intel.com/929349/325462-093-sdm-vol-1-2abcd-3abcd-4.pdf -O ./docs/docs.x86.pdf
```

The PDF is git-ignored (`*.x86.pdf`) and is only used while authoring content; it is not needed to
run or test the app, and it is not shipped in the container image.

Requirements: [uv](https://docs.astral.sh/uv/) (Python 3.12+), Node 20+ (Tailwind build only), and
Docker/kubectl for deployment.

```bash
make setup     # uv sync + npm ci
make dev       # build CSS, then run http://localhost:8000 with reload (downloads the embedding model once)
make test      # pytest
make check     # lint + tests + content validation + progress freshness (run before committing)
```

**NixOS:** if `uv run`/`make` fails with `ImportError: libstdc++.so.6: cannot open shared object file`,
run `export LD_LIBRARY_PATH=$NIX_LD_LIBRARY_PATH` first. Diagnosis: the failure is raised while importing
numpy's compiled extension (also hit by onnxruntime/fastembed), which needs `libstdc++.so.6`. NixOS keeps
no libstdc++ on the default library path, but the nix-ld library directory does contain it, so pointing
`LD_LIBRARY_PATH` there fixes it. Not dug into: why nix-ld does not already expose that directory to
extension modules loaded by uv's Python. Only affects this kind of host; Docker and other Linux/macOS setups
are unaffected, and PyMuPDF-only commands (`docx86 sdm ...`) work without it.

Looking up an instruction in the SDM while writing content:

```bash
uv run docx86 sdm find popcnt       # -> "1694-1696  POPCNT—Return the Count of Number of Bits Set to 1"
uv run docx86 sdm show popcnt       # prints those PDF pages as text
```

## Container and Kubernetes

```bash
make image IMAGE=registry.example.com/docx86 TAG=0.1.0
kubectl kustomize deploy/k8s            # render the manifests
kubectl apply -k deploy/k8s
```

Edit `images:` and the Ingress host in `deploy/k8s/kustomization.yaml` / `ingress.yaml` first. The
image is self-contained (content, search index and embedding model are baked in at build time), so
pods are stateless and need no network access. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

### Tracing (OpenTelemetry)

Off by default. To turn it on, set your collector's **OTLP/HTTP** endpoint (port 4318, not gRPC 4317), e.g.
uncomment `OTEL_EXPORTER_OTLP_ENDPOINT` in `deploy/k8s/kustomization.yaml`. Locally,
`OTEL_TRACES_EXPORTER=console make dev` prints spans to the terminal. Search text and client addresses are
**not** recorded unless you set `DOCX86_TRACE_USER_DATA=true`. Details, span list and failure behaviour:
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md#observability-opentelemetry-tracing).
